# Novel Bot developer console

React, TypeScript, Vite, and TanStack Router. The console uses the Go API for
registration, login, logout, and API-key management.

## Run locally

Install Node.js 22.12+ (or 24+) and pnpm. From the repository root:

```sh
pnpm --dir ui install --frozen-lockfile
make db
make migrate
make run-api
```

In another terminal:

```sh
make run-ui
```

Open **http://localhost:3000**. Create an account or sign in, then select
**Create API key**. Copy the generated key before dismissing the dialog.
A browser worker is only required when creating browser sessions; account and
key management work with the API, PostgreSQL, and Redis.

The Vite development server forwards `/v1`, `/docs`, and `/openapi.json` to
`http://127.0.0.1:8080`. To use another API address, copy `ui/.env.example` to
`ui/.env` and edit `API_PROXY_TARGET`, or override it when starting Vite:

```sh
API_PROXY_TARGET=http://127.0.0.1:9000 make run-ui
```

Backend credentials stay in the root `.env`. Do not put secrets in `VITE_*`
variables; Vite exposes those variables in client bundles.

## Authentication and keys

The account Bearer token is stored in tab-scoped `sessionStorage` so page reloads
can restore the login. Restoration validates it with `/v1/auth/me`; expiry and
HTTP 401 responses return to login. Sign-out requests server-side revocation and
clears local credentials even if the API is unreachable. In that case, the
server session remains valid until it expires.

Generated application keys live only in component memory until the one-time
dialog is dismissed. They are never saved in browser storage. The list displays
key IDs and metadata, not recoverable secrets. Use an application key as the
Bearer token for browser session requests; the account login token manages keys.

For a cookie-based production login, add a server/BFF that stores the account
session in a Secure, HttpOnly cookie with CSRF protection. The current API is
Bearer-based; this frontend follows that existing contract.

## Structure

```text
src/
  components/              Shared brand, icons, dialog, loading state
  features/
    auth/                  Login/register screens and account-session provider
    api-keys/              Key list, creation, one-time display, revocation
  lib/api.ts               Typed API client and consistent error handling
  routes/                  Thin TanStack Router entry points
  routeTree.gen.ts          Generated by the router; do not edit manually
  styles.css               Responsive console and form styles
```

## Verification

```sh
make check-ui
make build-ui
pnpm --dir ui exec playwright install chromium
pnpm --dir ui test
```

The default browser suite mocks API responses to check forms, rejection messages,
protected routes, one-time secrets, reloads, expiry, revocation, and mobile layout.
It uses its own Vite server on port 3001 and does not need backend services.

To also exercise the real registration/key lifecycle, provide an **isolated,
migrated test API** with disposable PostgreSQL/Redis data:

```sh
UI_TEST_API_TARGET=http://127.0.0.1:18080 pnpm --dir ui test
```

That optional test creates an account, issues a key, verifies authenticated access,
revokes the key, and logs in again. It leaves the account in the test database.
Use `PLAYWRIGHT_CHANNEL=chrome` to use an already installed Google Chrome instead
of downloading Playwright Chromium. Screenshots contain synthetic fixture data;
traces, videos, and automatic screenshots are disabled to avoid recording tokens.

## Production build

```sh
make build-ui
```

Deploy `ui/dist` through a static host/reverse proxy. Serve the frontend and API
under the same HTTPS origin: forward `/v1/*`, `/docs/*`, and `/openapi.json` to
`cmd/api`, and serve `index.html` for frontend routes such as `/login`, `/register`,
and `/api-keys`. The Vite proxy runs only during development. The frontend is not
yet bundled into the Go server or backend Docker images.
